# Personality Model Reference

> เอกสารอ้างอิงกลางสำหรับความหมายของ Personality Dimensions, Personality Traits และสเกลคะแนนที่ระบบใช้อยู่จริง ณ `QUESTION_VERSION = "2026-08-25-rpg-2"` และ `ALGORITHM_VERSION = "1.0.0"`
>
> เอกสารนี้ใช้สำหรับ authoring และ review ข้อมูล ไม่ใช่ข้อความที่ต้องแสดงแก่ผู้ทำแบบทดสอบ และไม่ใช่การจัดประเภทบุคลิกอย่างเป็นทางการจาก HoYoverse

## 1. ขอบเขตและแหล่งข้อมูลหลัก

เอกสารนี้รวบรวมข้อมูลจากแหล่งต่อไปนี้:

- แนวคิดและความหมายของโมเดล: `CONTEXT.md`
- ID และชนิดข้อมูล: `src/types/index.ts`
- คำถามและคะแนนต่อคำตอบ: `src/data/quiz/questions.ts`
- ชื่อและคำอธิบาย trait: `src/data/personality/traits.json`
- การ normalize และ matching: `src/engine/index.ts`
- ข้อจำกัดที่ตรวจด้วย Zod: `src/schemas/index.ts`

เมื่อเอกสารนี้ไม่ตรงกับโค้ด ให้ถือว่าโค้ด runtime และ schema คือพฤติกรรมที่ระบบทำจริง แล้วแก้เอกสารนี้ให้กลับมาตรงกัน

## 2. Personality Dimensions

Dimension คือแกนสองขั้วที่อธิบายแนวโน้มพฤติกรรมโดยรวม ค่าต่ำและค่าสูงไม่ใช่ “ไม่ดี” และ “ดี” แต่เป็นคนละทิศของแกนเดียวกัน

| ID               | ความหมายของค่าต่ำ / คะแนนดิบติดลบ                            | ความหมายของค่ากลาง            | ความหมายของค่าสูง / คะแนนดิบเป็นบวก                            |
| ---------------- | ------------------------------------------------------------ | ----------------------------- | -------------------------------------------------------------- |
| `social`         | Introverted — เอนเอียงไปทางพื้นที่ส่วนตัวหรือวงสังคมขนาดเล็ก | ปรับระดับการเข้าสังคมตามบริบท | Extroverted — เอนเอียงไปทางการเข้าหาและรับพลังจากปฏิสัมพันธ์   |
| `decision`       | Emotional — ให้น้ำหนักกับความรู้สึก คุณค่า และผลกระทบต่อคน   | ผสมเหตุผลกับคุณค่าและบริบท    | Rational — ให้น้ำหนักกับข้อเท็จจริง หลักฐาน และเกณฑ์เชิงเหตุผล |
| `lifestyle`      | Spontaneous / Flexible — ยืดหยุ่นและปรับตามสถานการณ์         | มีโครงคร่าว ๆ แต่เปลี่ยนได้   | Structured / Planned — ชอบระบบ แผน และความชัดเจนล่วงหน้า       |
| `adventure`      | Cautious — ให้ความสำคัญกับความแน่นอนและการลดความเสี่ยง       | ประเมินความเสี่ยงก่อนเลือก    | Adventurous — เปิดรับความท้าทาย ความใหม่ และความไม่แน่นอน      |
| `responsibility` | Free-spirited — ให้น้ำหนักกับอิสระและข้อผูกมัดที่ยืดหยุ่น    | สมดุลอิสระกับหน้าที่          | Duty-driven — ให้น้ำหนักกับหน้าที่ คำมั่น และผู้ที่พึ่งพาตน    |
| `expression`     | Reserved — เก็บความคิดหรืออารมณ์ไว้ภายในมากกว่า              | แสดงออกตามความไว้ใจและบริบท   | Expressive — สื่อสารตัวตน ความคิด และอารมณ์อย่างเปิดเผย        |

### การตีความค่าที่ normalize แล้ว

ผลลัพธ์ dimension ถูกแปลงเป็นจำนวนเต็ม `0–100`:

- `0` หมายถึงปลายด้านค่าต่ำที่สุดที่ question bank ปัจจุบันทำได้
- `50` คือกึ่งกลางเชิงคณิตศาสตร์ของช่วงที่ทำได้ ไม่ได้หมายความว่า “ไม่มีบุคลิก”
- `100` หมายถึงปลายด้านค่าสูงที่สุดที่ question bank ปัจจุบันทำได้
- ค่าระหว่างกลางคือระดับความเอนเอียงบนแกนนั้น ไม่ใช่หมวดประเภทแบบตายตัว

ระบบยังไม่ได้กำหนด label ทางการสำหรับช่วงย่อย เช่น `0–20` หรือ `80–100` จึงไม่ควรสร้างชื่อช่วงขึ้นเองโดยไม่มี design decision เพิ่มเติม

## 3. Personality Traits

Trait คือคุณลักษณะเชิงรายละเอียดแบบทิศเดียว คะแนนมากหมายถึงระบบพบ signal ของ trait นั้นมากขึ้น คะแนนน้อยหมายถึงพบ signal น้อยลง ไม่ได้แปลว่าบุคคลนั้นมี “trait ตรงข้าม” โดยอัตโนมัติ

| ID                | ชื่อภาษาไทย        | ความหมายที่ใช้ในระบบ                               |
| ----------------- | ------------------ | -------------------------------------------------- |
| `passion`         | เปี่ยมพลัง         | ขับเคลื่อนด้วยความสนใจและความรู้สึกแรงกล้า         |
| `enthusiasm`      | กระตือรือร้น       | ส่งต่อพลังและความตื่นเต้นให้คนรอบตัว               |
| `selfExpression`  | แสดงตัวตน          | สื่อสารตัวตน ความคิด หรือรสนิยมอย่างชัดเจน         |
| `determination`   | มุ่งมั่น           | เดินหน้าต่อแม้ต้องพบอุปสรรค                        |
| `optimism`        | มองโลกในแง่ดี      | มองเห็นความหวังและความเป็นไปได้                    |
| `ideals`          | ยึดอุดมการณ์       | ให้ความสำคัญกับสิ่งที่เชื่อว่าถูกต้องและมีความหมาย |
| `adaptability`    | ปรับตัวเก่ง        | รับมือกับสถานการณ์ใหม่และเปลี่ยนวิธีได้            |
| `responsibility`  | รับผิดชอบ          | ดูแลผลของการกระทำและคนที่พึ่งพาได้                 |
| `creativity`      | สร้างสรรค์         | มองเห็นวิธีหรือความเป็นไปได้ใหม่                   |
| `perseverance`    | พากเพียร           | ทำงานกับเป้าหมายระยะยาวอย่างต่อเนื่อง              |
| `freedom`         | รักอิสรภาพ         | ต้องการเลือกเส้นทางและวิถีของตนเอง                 |
| `acceptance`      | ยอมรับความแตกต่าง  | เปิดพื้นที่ให้ผู้คนและมุมมองที่ต่างกัน             |
| `sensitivity`     | ละเอียดอ่อน        | รับรู้บรรยากาศและผลกระทบทางอารมณ์ได้ไว             |
| `selflessness`    | เสียสละ            | พร้อมวางประโยชน์ของผู้อื่นไว้ก่อนตน                |
| `individuality`   | มีเอกลักษณ์        | ยืนหยัดในตัวตนและมุมมองของตน                       |
| `independence`    | พึ่งพาตนเอง        | ตัดสินใจและจัดการชีวิตด้วยตนเอง                    |
| `confidence`      | มั่นใจ             | เชื่อมั่นในความสามารถและการตัดสินใจของตน           |
| `nonconformity`   | ไม่ตามกรอบ         | ตั้งคำถามต่อกฎหรือความคาดหวังที่ไม่สมเหตุผล        |
| `growth`          | เติบโต             | มองการเปลี่ยนแปลงเป็นโอกาสพัฒนาตน                  |
| `curiosity`       | ใฝ่รู้             | อยากสำรวจและทำความเข้าใจสิ่งที่ยังไม่รู้           |
| `knowledge`       | ใฝ่ความรู้         | ให้คุณค่ากับข้อมูล ความเข้าใจ และความจริง          |
| `learning`        | เรียนรู้อยู่เสมอ   | พัฒนาผ่านการฝึกและประสบการณ์                       |
| `selfDevelopment` | พัฒนาตน            | ตั้งใจยกระดับทักษะและขีดความสามารถของตน            |
| `innerConflict`   | มีความขัดแย้งภายใน | เผชิญแรงดึงระหว่างคุณค่า ความรู้สึก หรือบทบาท      |
| `contradiction`   | มีหลายด้าน         | มีแนวโน้มหรือความต้องการที่ดึงกันคนละทิศ           |
| `identity`        | ค้นหาตัวตน         | ให้ความสำคัญกับการนิยามตัวตนและที่มา               |
| `introspection`   | ใคร่ครวญ           | ทบทวนความคิดและความรู้สึกของตนอย่างลึกซึ้ง         |
| `resilience`      | ฟื้นตัวเก่ง        | ฟื้นตัวและเดินหน้าต่อหลังความยากลำบาก              |
| `resolve`         | แน่วแน่            | ยึดมั่นในคำตัดสินและเป้าหมายที่เลือก               |
| `stability`       | มั่นคง             | รักษาความสงบและความต่อเนื่องได้                    |
| `discipline`      | มีวินัย            | ทำตามระบบหรือข้อผูกพันอย่างสม่ำเสมอ                |
| `reliability`     | น่าเชื่อถือ        | เป็นคนที่ผู้อื่นพึ่งพาได้เมื่อจำเป็น               |
| `leadership`      | ภาวะผู้นำ          | ช่วยให้คนอื่นเห็นทิศทางและลงมือร่วมกัน             |
| `empathy`         | เห็นอกเห็นใจ       | เข้าใจและคำนึงถึงประสบการณ์ของผู้อื่น              |
| `ambition`        | ทะเยอทะยาน         | ต้องการบรรลุเป้าหมายที่ท้าทายและกว้างไกล           |
| `loyalty`         | ภักดี              | ยืนข้างคน กลุ่ม หรือคำมั่นที่ให้ความสำคัญ          |
| `idealism`        | อุดมคติ            | เชื่อว่าคุณค่าที่ดีกว่าสามารถเป็นจริงได้           |
| `humor`           | อารมณ์ขัน          | ใช้ความขบขันสร้างมุมมองหรือความเชื่อมโยง           |
| `competitiveness` | ชอบแข่งขัน         | มีแรงขับจากการทดสอบความสามารถกับมาตรฐานหรือผู้อื่น |

## 4. สเกลคะแนน

ระบบมีหลายสเกลซึ่งห้ามนำไปตีความปนกัน:

| ชั้นข้อมูล                         | สเกลปัจจุบัน                                               | ความหมาย                                                                  |
| ---------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------- |
| Dimension delta ต่อคำตอบ           | โดย convention ใช้`-3..3`                                  | ทิศและความแรงที่คำตอบขยับ dimension;`0` หรือ key ที่ไม่ระบุหมายถึงไม่ขยับ |
| Trait contribution ต่อคำตอบ        | โดย convention ใช้ค่าบวกขนาดเล็ก ปัจจุบันมักเป็น`0.1..0.3` | หลักฐานสนับสนุน trait; key ที่ไม่ระบุเท่ากับ`0`                           |
| User dimension profile             | จำนวนเต็ม`0..100`                                          | ค่าที่ normalize จากช่วงต่ำสุด–สูงสุดซึ่งทำได้จริงใน question bank        |
| User trait profile                 | ทศนิยม`0..1`                                               | ผลรวม contribution หารด้วยค่าสูงสุดที่ทำได้จริง แล้วปัด 4 ตำแหน่ง         |
| Character dimension profile        | จำนวนเต็ม`0..100`                                          | ค่าตีความบุคลิกตัวละครบนแกน dimension                                     |
| Character trait weight             | ทศนิยม`0..1`                                               | ความเด่นหรือความสำคัญของ trait ในโปรไฟล์ตัวละคร                           |
| Element trait weight               | ทศนิยม`0..1`                                               | ความสำคัญสัมพัทธ์ของ trait ต่อธีมธาตุ                                     |
| Compatibility / Affinity ที่แสดงผล | จำนวนเต็ม`0..100%`                                         | ผล matching หลังคำนวณและปัดเพื่อแสดงผล                                    |

### ระดับความแรงของ Dimension delta

|               ค่า | แนวทางตีความสำหรับผู้เขียนคำถาม |
| ----------------: | ------------------------------- |
|              `-3` | signal ชัดเจนมากไปทางปลายค่าต่ำ |
|              `-2` | signal ชัดเจนไปทางปลายค่าต่ำ    |
|              `-1` | signal เล็กน้อยไปทางปลายค่าต่ำ  |
| `0` / ไม่ระบุ key | ไม่ให้ signal กับ dimension นี้ |
|               `1` | signal เล็กน้อยไปทางปลายค่าสูง  |
|               `2` | signal ชัดเจนไปทางปลายค่าสูง    |
|               `3` | signal ชัดเจนมากไปทางปลายค่าสูง |

ค่าข้างต้นเป็น authoring convention ที่ข้อมูลปัจจุบันใช้ ไม่ใช่ข้อจำกัดที่ `scoredQuizQuestionSchema` บังคับในขณะนี้

## 5. การคำนวณโปรไฟล์ผู้ใช้

### Dimension normalization

สำหรับแต่ละ dimension:

```text
raw = ผลรวม dimension delta ของคำตอบที่ผู้ใช้เลือก
minimum = ผลรวมคะแนนต่ำสุดที่เลือกได้ของทุกคำถาม
maximum = ผลรวมคะแนนสูงสุดที่เลือกได้ของทุกคำถาม

normalized = round(clamp((raw - minimum) / (maximum - minimum) × 100, 0, 100))
```

`minimum` และ `maximum` มาจาก question bank จริง ไม่ได้สมมติจากจำนวนข้อคูณ `-3` หรือ `3` ดังนั้นการแก้คะแนนคำถามจะเปลี่ยนฐาน normalization โดยอัตโนมัติ

### Trait normalization

สำหรับแต่ละ trait:

```text
raw = ผลรวม trait contribution ของคำตอบที่ผู้ใช้เลือก
maximum = ผลรวม contribution สูงสุดที่เลือกได้ของทุกคำถาม

normalized = round(clamp(raw / maximum, 0, 1), 4 ตำแหน่ง)
```

ถ้า trait ไม่มีคะแนนใน question bank เลย (`maximum = 0`) ระบบให้ค่า `0`

## 6. กติกา Authoring และ Review

- คำตอบหนึ่งข้ออาจกระทบหลาย dimensions และหลาย traits ได้
- คะแนน dimension ติดลบหมายถึงเอนไปทางปลายค่าต่ำของแกน ไม่ใช่คะแนนเสียหรือบุคลิกเชิงลบ
- Trait contribution ปัจจุบันเป็นค่าที่สนับสนุน trait เท่านั้น อย่าใช้ค่าติดลบเพื่อสื่อ “trait ตรงข้าม” โดยไม่มีการออกแบบ normalization ใหม่
- หลีกเลี่ยง trait ที่ความหมายซ้ำกันโดยเปลี่ยนเพียงชื่อเล็กน้อย
- คะแนนของตัวละครและธาตุเป็น fan-made interpretation และต้อง review เทียบ lore/หลักฐาน
- Character Match และ Vision Affinity ต้องคำนวณแยกกันเสมอ; ห้ามหา Vision จากธาตุของตัวละครที่ชนะ
- เมื่อแก้ question bank หรือความหมายคะแนน ให้พิจารณาเปลี่ยน `QUESTION_VERSION`; เมื่อแก้สูตร matching/normalization ให้พิจารณาเปลี่ยน `ALGORITHM_VERSION`

| Question bank มี 36 ข้อ                                   | บังคับด้วย`.length(36)`                                             |
| Question bank ปัจจุบันมี 6 ข้อต่อ dimension               | เป็นข้อมูลจริง แต่ validator กำหนดเพียงอย่างน้อย 4 ข้อต่อ dimension |
| Question dimension delta อยู่ใน`-3..3`                    | ใช้เป็น convention แต่ยังไม่บังคับ min/max ใน Zod                   |
| Question dimension delta เป็นจำนวนเต็ม                    | ข้อมูลปัจจุบันใช้จำนวนเต็ม แต่ยังไม่บังคับ`.int()` ใน Zod           |
| Question trait contribution ไม่ติดลบและอยู่ในช่วงที่กำหนด | ข้อมูลปัจจุบันใช้ค่าบวกขนาดเล็ก แต่ schema ยังรับ number ใด ๆ       |

### Checklist เมื่อ audit

1. ตรวจว่า polarity ของทุก dimension ตรงกับตารางในหัวข้อ 2
2. ตรวจว่า trait ID, label และ description ตรงกับ `traits.json`
3. ตรวจว่า dimension delta ของคำตอบอยู่ใน `-3..3` และเป็นจำนวนเต็ม
4. ตรวจว่า trait contribution ไม่ติดลบและมีขนาดสอดคล้องกับคำถามอื่น
5. ตรวจคำตอบทั้งชุดของแต่ละคำถามว่าไม่มีตัวเลือกหนึ่งให้ signal หลายด้านแรงเกินสมควร
6. ตรวจ balance หลังแก้ question bank เพราะ theoretical min/max จะเปลี่ยนตามข้อมูล
7. รัน `corepack pnpm validate:data`, `corepack pnpm verify:engine`, `corepack pnpm lint` และ `corepack pnpm build`
