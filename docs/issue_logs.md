## UX-01 — เริ่มรอบใหม่แล้วยังแสดงชื่อเดิม

**ความสำคัญ:** P1  
**สถานะ:** เปิด — ยืนยันจากโค้ด

### ปัญหา

เมื่อกดเริ่มทำแบบทดสอบรอบใหม่ กล่องกรอกชื่อแสดงชื่อจากรอบก่อน ทำให้ผู้ใช้ต้องลบเองก่อนเริ่ม

### หลักฐานปัจจุบัน

`LandingPage` ตั้งค่าเริ่มต้นของ field จาก `readPlayerName()` ทุกครั้งที่ mount และ `readPlayerName()` อ่าน `teyvat-player-name-v1` จาก storage โดยตรง จึงคืนชื่อเดิมให้รอบใหม่

### PRD / เกณฑ์ยอมรับ

- การกด “ทำแบบทดสอบใหม่” จาก Result หรือ reset จาก Quiz ต้องเปิด name dialog ด้วยค่าว่าง
- การกลับมา resume แบบทดสอบที่ยังไม่เสร็จ ต้องยังคงชื่อเดิมได้
- ชื่อที่กรอกในรอบใหม่ต้องถูกบันทึกและใช้กับผลลัพธ์รอบนั้นตามเดิม

### แนวทางแก้

แยก intent `new attempt` ออกจาก `resume` ใน route state หรือ hook แล้ว reset state ของ field เฉพาะกรณีเริ่มรอบใหม่ โดยไม่ลบข้อมูลก่อนผู้ใช้ยืนยันชื่อ

## UX-02 — ความสูงของ Quiz panel เปลี่ยนตามเนื้อหา

**ความสำคัญ:** P2  
**สถานะ:** เปิด — ยืนยันจากโค้ด

### ปัญหา

เมื่อเปลี่ยนคำถามหรือย้อนกลับ ความสูงของ card เปลี่ยนตามความยาวของ prompt/ตัวเลือก ทำให้หน้าจอดูขยับขึ้นลง

### หลักฐานปัจจุบัน

`.question-card` ไม่มี `min-height` หรือ layout reservation; prompt และตัวเลือกเป็นเนื้อหาความยาวแปรผันทั้งหมด

### PRD / เกณฑ์ยอมรับ

- ที่ viewport desktop และ tablet ความสูงของพื้นที่คำถามต้องคงที่หรือเปลี่ยนน้อยจนไม่เกิด layout jump ที่สังเกตได้
- ที่ mobile ต้องไม่ตัดข้อความ ไม่ซ่อนตัวเลือก และยังเลื่อนได้ตามปกติ
- ไม่ลดขนาดฟอนต์ต่ำกว่ามาตรฐานการอ่านเพื่อบังคับให้ข้อความพอดี

### แนวทางแก้

กำหนด `min-height` สำหรับ card ใน viewport กว้าง และใช้ responsive layout ที่ปล่อยให้ card สูงตามเนื้อหาบน mobile; ตรวจทุกภาษาและคำถามที่ยาวที่สุด

## UX-03 — กด Back หลังจบ Quiz แล้วย้อนเข้า flow เดิมได้

**ความสำคัญ:** P1  
**สถานะ:** เปิด — พบว่าการป้องกันยังไม่ครบ

### ปัญหา

หลังจบแบบทดสอบ ผู้ใช้ยังสามารถย้อนกลับไปหน้า Quiz ผ่าน browser Back และเห็น/แก้ flow เดิมได้

### หลักฐานปัจจุบัน

`MatchingPage` ใช้ `navigate("/result", { replace: true })` จึงเอาหน้า Matching ออกจาก history แต่ยังเหลือหน้า Quiz อยู่ใน history และ `QuizPage` ยัง render เมื่อมี completed progress

### PRD / เกณฑ์ยอมรับ

- หลังเข้าหน้า Result แล้ว Browser Back ต้องไม่พาผู้ใช้กลับไปแก้คำตอบของรอบที่คำนวณเสร็จแล้ว
- การเปิด `/quiz` หลังมี completed progress ต้องพาไปจุดเริ่มรอบใหม่หรือ Result ตาม intent ที่กำหนดอย่างชัดเจน
- ต้องไม่ทำให้ back navigation ระหว่างทำแบบทดสอบ (ก่อนจบ) ใช้ไม่ได้

### แนวทางแก้

กำหนด completed progress เป็น terminal state ใน `QuizPage` และปรับ history transition ตอนจบให้ไม่มี route ที่แก้คำตอบเดิมได้; ตรวจ Browser Back/Forward, refresh และ deep link

## UX-04 — ปุ่มกลับจาก Character Detail ไม่พากลับ Result

**ความสำคัญ:** P1  
**สถานะ:** เปิด — ยืนยันจากโค้ด

### ปัญหา

จากหน้า Result เมื่อกด “ดูตัวละคร” แล้วกดปุ่มกลับใน Character Detail ระบบพาไปหน้า Characters Directory แทนหน้า Result

### หลักฐานปัจจุบัน

`CharacterPage` ใช้ `<Link to="/characters">` แบบตายตัว และ `ResultPage` ไม่ส่ง origin state ไปพร้อม link ของ Character Detail

### PRD / เกณฑ์ยอมรับ

- หากเข้าหน้า Character Detail จาก Result ปุ่มกลับในหน้า detail ต้องกลับไป Result เดิม
- หากเข้าจาก Characters Directory ปุ่มกลับต้องกลับไป Directory
- refresh หรือ direct URL ต้องมี fallback ที่คาดเดาได้ (Characters Directory)

### แนวทางแก้

ส่ง `origin` ผ่าน router state จากทุกจุดเข้า Character Detail แล้วเลือก destination ตาม origin; ใช้ `/characters` เป็น fallback เมื่อไม่มี state

## UX-05 — ชื่อตัวละครล้นในภาพ Share Card

**ความสำคัญ:** P1  
**สถานะ:** เปิด — ยืนยันจากโค้ด

### ปัญหา

ภาพ Share Card ที่ดาวน์โหลดใช้ขนาดฟอนต์ชื่อคงที่ จึงทำให้ชื่อยาว เช่น `yumemizuki_mizuki`, `sangonomiya_kokomi` และ `neuvillette` ล้นพื้นที่ด้านขวา

### หลักฐานปัจจุบัน

`downloadShareCard()` วาดชื่อด้วยฟอนต์ `92px` และ `fillText()` โดยไม่มีการวัดความกว้าง, ลดขนาด, wrap หรือ truncate

### PRD / เกณฑ์ยอมรับ

- ชื่อตัวละครทุกตัวต้องอยู่ภายในพื้นที่ชื่อของ PNG ขนาด 1080 × 1080 โดยไม่ทับ title หรือส่วนอื่นของ card
- ชื่อสั้นต้องคง typography ปัจจุบัน; ชื่อยาวให้ลดขนาดแบบมีขั้นต่ำที่อ่านได้ก่อนพิจารณา truncate
- ตรวจอย่างน้อย `neuvillette`, `yumemizuki_mizuki` และ `sangonomiya_kokomi` ทั้งไทยและอังกฤษ

### แนวทางแก้

สร้าง helper วัดความกว้างด้วย `measureText()` แล้วลด font size จนพอดีกับพื้นที่ 375px (จาก x=555 ถึง x=930); ถ้าต่ำกว่าขนาดขั้นต่ำให้ตัดด้วย ellipsis อย่างปลอดภัย
